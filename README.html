Discord Chat Bridge — Setup Guide

The bridge connects your guild chat in-game with a Discord channel, in both directions: guild chat shows up in Discord, and Discord messages show up in guild chat.

There are two parts to set up:

  1. The relay — a small web service. Set up once by whoever runs the bridge (the "operator").
  2. The DiscordBridge.ini file — a small settings file that each player fills in.

If you're a player and someone else already runs the relay, skip straight to Part 2 — all you need is the ini file and a key from the operator.

Part 1 — Setting up the relay (operator only)

The relay's settings are given as environment variables on the server that hosts it (never typed into appsettings.json, because that file is shared publicly). These are the ones that matter:

SettingWhat it is
Discord__WebhookUrl The Discord webhook for your bridge channel. In Discord: channel settings → Integrations → Webhooks → create one and copy its URL. This is what sends guild chat into Discord.
Relay__ApiKeys__guild A password you make up that lets players use the relay. Generate one in PowerShell with [guid]::NewGuid().ToString(), then give it to your guild members — it's the key they put in their ini file.
Discord__BotToken A Discord bot's token. Needed for the Discord → game direction. The bot must be in your server and able to read the bridge channel.
Discord__ChannelId The ID number of the bridge channel (right-click the channel in Discord → Copy Channel ID; you may need Developer Mode enabled in Discord's settings).
Discord__Stage2Enabled Set to true to turn on the Discord → game direction. Leave it off and the bridge is one-way (game → Discord only).
Optional — automatic tidy-up: set Discord__CleanupEnabled to true and the relay deletes bridge-channel messages older than about 5 hours (pinned messages are kept). The channel works like a live ticker rather than an archive. The bot needs the Manage Messages and Read Message History permissions for this.

To check everything is working, open https://<your-relay-address>/api/v1/health in a browser — it should show a page of status information, including whether the Discord webhook was picked up.

Part 2 — Filling in DiscordBridge.ini (every player)

Put DiscordBridge.ini in the same folder as SWGCommandExtension.dll. Only three settings are required:

[DiscordBridge]
enabled=1
endpoint=https://your-relay-address/relay
key=paste-the-key-you-were-given-here
SettingWhat to put
enabled1 to start the bridge automatically when the game loads, 0 to keep it off until you type /emu discord on.
endpointThe relay's web address — the operator will tell you what it is.
keyThe key handed out by the operator. The bridge does nothing while this is empty.

There are also a few optional settings — client_id, character and galaxy — which just label you in the operator's logs. You can leave them blank.

Two things to be careful of:
  • Your key is like a password — don't post or share it.
  • Comments in the file (lines starting with ;) must be on their own line. Writing a note at the end of a setting line breaks that setting.

Handy in-game commands

/emu discord onTurns the bridge on (and re-reads the ini file, so edits apply without restarting the game).
/emu discord offTurns the bridge off.
/emu discord statusShows whether the bridge is running and tells you if something (like a missing key) is wrong.
